# `test/` — бандл для ИИ-анализа

> Папка для передачи проекта моделям (Kimi, Qwen, DeepSeek, Claude и т.д.)
> на аудит. Снимок: **03.10.2026**, коммит `749562e`.

## Что здесь и зачем

| Файл | Для кого | Что даёт |
|---|---|---|
| **`Для анализа.txt`** | модель, которой нужен один файл | Самодостаточный снимок: стек, что сделано, чего нет, команды проверки. Начни с него |
| **`СВОДКА.md`** | модель для глубокого аудита | Все правила проекта в одном файле (65 КБ, 8 секций) с оглавлением и ссылкой «секция → исходный файл» |
| **`../Что сделано.txt`** | владелец проекта | Журнал по этапам: задача → сделано → чем проверено → остаток. В `test/` осталась заглушка-указатель |
| **`../Что доделать.txt`** | владелец проекта | Бэклог с критериями приёмки и приоритетами. В `test/` осталась заглушка-указатель |
| **`ИНВЕНТАРЬ-ТЕСТОВ.md`** | модель, которой важно про покрытие | Состояние проверок: 0 автотестов, 9 ручных скриптов, список пробелов |
| **`Промты.txt`** | владелец + модель | Готовые промты: аудит, перевод раздела на хранилище, написание тестов, разбор бага |
| **`AGENTS.md`** | любой ИИ-агент, попавший в папку | Копия корневого правил проекта, чтобы агент прочитал правила первыми |

## С чего читать

**Аудит проекта целиком** → `Для анализа.txt`, потом `СВОДКА.md`, потом
[`../Что доделать.txt`](../Что%20доделать.txt).

**«Что там сломано?»** → `ИНВЕНТАРЬ-ТЕСТОВ.md`, раздел «Известные пробелы
покрытия».

**Просто починить задачу** → `Промты.txt`, нужный раздел.

## Правила чтения снимка

1. **Числа — результат прогона, а не пересказ.** Если счётчик в снимке
   расходится с репозиторием, **верен репозиторий**. Пересчитай и обнови
   файл, а не верь строке.
2. **«0 тестов» — это факт, а не пропуск.** Vitest и Playwright в проекте не
   установлены. Утверждать «покрыто тестами» нельзя.
3. **Отсутствие функции ≠ пробел покрытия.** Если авторизации нет, то и тестов
   на неё нет — это разные вещи. Не «покрыть» то, чего не существует.
4. **Внешние консультации — не правила проекта.** Шесть файлов собраны в
   [`../консультации/`](../консультации/README.md): `Анализ.txt`,
   `Анализ1.txt` … `Анализ4.txt` и `Промт.txt`. Это мнение сторонних моделей,
   а не проектные требования. `Анализ.txt` рекомендует вернуться на Next.js,
   `Промт.txt` — промты под TinaCMS. Оба вопроса закрыты в пользу текущего
   стека. Не предлагай вернуться на Next.js или внедрять TinaCMS, не
   перечитав `../консультации/README.md`.
5. **Проверяй утверждение по файлу, а не по уверенности автора.** Четыре
   консультации из шести содержат находки, не выдерживающие проверки: CLS на
   файлах с зарезервированным CSS-местом, относительный `Sitemap:`,
   `Disallow: /admin` рядом с `noindex`, потерянный фолбэк `description`,
   сокращение набора тестов до трёх файлов. Утверждение «я проверил» в этих
   файлах не является основанием. Зато две находки подтвердились и были
   приняты — питфолы 24 и 25.

## Как обновить

| Что меняешь | Что править |
|---|---|
| Правила проекта | `docs/AGENTS-*.md`, потом `node scripts/gen-svodka.mjs` |
| Состояние кода | `test/Для анализа.txt`, `Что сделано.txt` (корень) |
| Бэклог | `Что доделать.txt` (корень) |
| Числа проверок | `test/ИНВЕНТАРЬ-ТЕСТОВ.md` |
| Корневое правило | `AGENTS.md`, потом скопировать в `test/AGENTS.md` |

`СВОДКА.md` **генерируется**, не пишется руками:
`node scripts/gen-svodka.mjs` пересобирает его из `docs/AGENTS-*.md` —
пересчитывает размеры, строит оглавление и ссылки на секции. Правки в
`СВОДКА.md` руками будут потеряны при следующей генерации.

> Про правило «счётчики в доках устаревают молча»: числа в этих файлах —
> копии результатов прогонов. Если правишь цифру — прогоняй команду, которая
> её даёт, и вставляй её вывод, а не переписывай на глаз.

## Чего в папке нет

Автотестов. Скрипты проверки лежат в
`C:\Users\PC\AppData\Local\Temp\opencode`, а не здесь: до появления
фреймворка не плодить вторую тестовую систему. При переходе на
Vitest/Playwright (`../Что доделать.txt`, пункт 1) проверки переносятся в
репозиторий.

Копий журнала и бэклога здесь намеренно нет: две копии расходятся, и никто
не заметит, потому что обе выглядят актуально. Канонические файлы — в корне,
в `test/` лежат заглушки-указатели.
