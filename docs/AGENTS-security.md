# Security Rules и абсолютные запреты

## Статус безопасности (честно)

| Слой | Состояние |
|------|-----------|
| `/api/admin/*` | **Открыт.** Любой может создать/удалить новость |
| `/admin/**` | **Открыт.** Любая страница панели доступна без входа |
| Авторизация | **Отсутствует.** В исходнике был `/login`, не перенесён |
| CSRF | Отсутствует. Cookie-сессий нет, токенов нет — но и защиты нет |
| Rate limiting | Отсутствует |
| Валидация ввода | Есть на `/api/admin/posts` (заголовок, тип, JSON, `id`) |
| Экранирование | Astro экранирует по умолчанию; `{@html}` не используется |
| SQL | Не используется (JSON-хранилище) |
| Секреты в репозитории | Нет. `.env` не отслеживается, `.env.example` — да |
| Зависимости | `npm run audit:prod` (`--omit=dev --audit-level=high`) |

**Это блокер выката, не «долг на будущее».** До появления авторизации панель нельзя публиковать в интернет.

## Абсолютные запреты

| ❌ Никогда | Почему |
|-----------|--------|
| Не коммитить `.env` | Секреты попадают в историю навсегда |
| Не выводить секрет в HTML/бандл | Клиентский JS виден любому |
| Не использовать `innerHTML` для пользовательских данных | XSS. Текст из админки — пользовательский ввод |
| Не отключать экранирование Astro (`set:html`) ради «красивого» вывода | XSS через контент-редактор |
| Не писать секрет в `src/content/*.json` | Файл в репозитории |
| Не открывать `/api/admin/*` без проверки прав | Любой посетитель перепишет сайт |
| Не возвращать `ssr.noExternal: ['react-slick']` | Ломает dev (pitfall 1) — «починить» безопасность не выйдет |
| Не менять публичные компоненты «по вкусу» | Ломает главное требование — паритет |
| Не выдавать 500 стеком в проде | Утечка путей и версий |

## Правила для работы с контентом

Поля из админки — **недоверенный ввод**:

1. Валидировать на сервере (`src/pages/api/admin/posts.ts`), а не только в форме.
2. Ограничивать длину: `title` ≤ 200, `excerpt` ≤ 500, `content` ≤ 100 000.
3. `image` — только `http(s)`/`/`, никаких `javascript:` и `data:`.
4. Рендерить текст как текст. Если нужен HTML — санировать явно и осознанно.
5. Публичная модель (`PublicNews`) не должна протекать внутренними полями наружу.

## Что делать при добавлении авторизации

1. Сессия — **httpOnly + SameSite=Lax + Secure** cookie. Не `localStorage`.
2. Пароль — **argon2id** или **bcrypt**, не SHA-256 и не MD5.
3. `/api/admin/*` — проверка прав **на каждый запрос**, не только на страницах.
4. `GET` публичного контента — остаётся без прав.
5. Сравнение — **timing-safe**. Проверка прав — **fail closed** (нет токена = 401, не «пропустить»).
6. Выход из системы инвалидирует сессию на сервере.
7. Открытый редирект — запрет: принимать только пути внутри `/admin`.

**Проверка после внедрения:**

```bash
node C:/Users/PC/AppData/Local/Temp/opencode/smoke.mjs
```

Без авторизации `/admin` отдаёт 200 — после внедрения должен отдавать **401/302**, а тесты маршрутов обновить.

## Чеклист безопасности перед продом

- [ ] `/admin` и `/api/admin/*` закрыты авторизацией
- [ ] `git ls-files | Select-String -Pattern '^\.env$'` — пусто
- [ ] `.env.example` не содержит реальных значений
- [ ] `npm run audit:prod` — exit 0
- [ ] Нет `set:html` / `innerHTML` с пользовательскими данными
- [ ] Ошибки API возвращают текст, не стек
- [ ] Cookie: `httpOnly`, `SameSite`, `Secure` (в проде)
- [ ] `NLB_CONTENT_DIR` указывает на каталог вне веб-корня

## Известные ограничения хранилища

- JSON-файл — **не** для конкурентной записи. Два одновременных `PUT` могут перетереть друг друга (последний выигрывает).
- Нет истории версий: правка перезаписывает запись.
- Нет бэкапа из приложения.
- Файл целиком в памяти при каждом чтении — при росте контента это заметно.

Это ограничения MVP-хранилища, а не баги. Переход на БД снимает все четыре. Записать сюда при миграции.
