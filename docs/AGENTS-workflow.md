# Workflow (5 этапов) и шаблоны промтов

## Этап 0 — Чтение (обязательный)

Прочитать **до** правки кода:

1. `AGENTS.md` — гипер-краткое резюме и навигация.
2. `docs/AGENTS-porting.md` — если трогаешь публичную часть.
3. `docs/AGENTS-pitfalls.md` — **всегда**. Там 25 уже пойманные грабли.
4. `docs/AGENTS-content-admin.md` — если трогаешь контент или админку.
5. Сам исходник `D:\nlb-studio6-main` — если меняешь публичный компонент.

Правило: **не начинать правку сразу после постановки задачи.** 5 минут чтения экономят час отладки.

## Этап 1 — План

Писать ответ в формате:

```
Что делаю:      <1 предложение>
Где:            <полные пути файлов>
Почему так:     <архитектурное решение, 1-2 предложения>
Риски:          <что может сломаться>
Проверка:       <чем проверять>
```

План у пользователя **запрашивается**, если задача неоднозначна. Не угадывать архитектуру.

## Этап 2 — Реализация

| Правило | Почему |
|---------|--------|
| TS strict, без `any` | Ошибка должна ловиться компилятором |
| Данные — пропсами из `.astro` | React-компонент не ходит в хранилище сам |
| Логика хранилища — в `src/lib/` | Одно место для тестирования |
| Клиент проверяет `res.ok` | Иначе «Сохранено» при ошибке |
| Валидация на сервере | Форму можно обойти |
| Комментарии не добавлять | Код говорит сам; JSDoc — только для экспортируемых типов по просьбе |
| Публичные компоненты — механические правки | Паритет с исходником |

## Этап 3 — Тесты

**Сейчас автотестов в проекте нет** — это долг, а не покрытие.

Пока фреймворка нет, «тест» = прогон скриптов из `%TEMP%\opencode` + ручная проверка в браузере:

| Что изменилось | Что прогнать |
|----------------|--------------|
| Публичный компонент | `smoke.mjs` + `compare-src.mjs` + браузер (слайдер, формы) |
| Контент/хранилище/API | `test-loop.mjs` + `test-api.mjs` + `test-news.mjs` |
| Роутинг/`getStaticPaths` | `smoke.mjs` + `audit-http.mjs` |
| Конфиг/адаптер | `run-build.cjs` **и** dev-сервер (pitfall 1) |
| CSS | Браузер: computed styles, не «страница 200» |

Планируется Vitest (юнит: `src/lib/content.ts`, `formatDate`) + Playwright (E2E: замкнутый цикл админка → сайт). См. `Что доделать.txt`.

## Этап 4 — Верификация

Полный чеклист — `docs/AGENTS-production.md`. Минимум перед «готово»:

1. `astro build` — зелёный (код возврата через `spawnSync`).
2. `smoke.mjs` — 69/69.
3. Если трогал контент — `test-loop.mjs` + `test-api.mjs`, хранилище возвращено к сиду.
4. Если трогал публичную часть — `compare-src.mjs`, отличия только механические.
5. Если трогал UI — руками в браузере.
6. Документация обновлена **в этом же коммите**.

## Шаблоны промтов

### Портирование компонента

```
Портируй <файл> из D:\nlb-studio6-main в Astro-проект D:\Astro tinacms.

Правила:
- Паритет 1:1. Не редизайнить, не менять тексты, классы, порядок элементов.
- Разрешено: относительные импорты, v3-эквиваленты классов (size-9 → h-9 w-9),
  SSR-безопасность, экспорт данных наружу.
- Прочитай docs/AGENTS-porting.md и docs/AGENTS-pitfalls.md.
- После: node %TEMP%\opencode\compare-src.mjs и %TEMP%\opencode\smoke.mjs.
```

### Секция админки на хранилище

```
Сделай раздел /admin/<section> рабочим с хранилищем вместо MOCK_*.

Требования:
- Модель данных в src/lib/content.ts рядом с существующей (паттерн постов).
- API в src/pages/api/admin/, export const prerender = false, валидация на сервере.
- UI — серверный Astro + vanilla JS, как в /admin/content.
- Абсолютное id: Number(null) === 0 — проверять отсутствие ДО Number().
- Клиент проверяет res.ok ДО показа «Сохранено».
- Публикация должна быть видна на сайте без пересборки.
- После: grep -rn "MOCK_" src/pages/admin/ должен опустеть,
  test-loop.mjs + test-api.mjs зелёные.
```

### Баг

```
Симптом: <что наблюдается>
Ошибка: <точный текст из консоли/терминала>
Где:     <маршрут или файл>

Прежде чем чинить:
- это баг кода или баг проверки? (pitfall 20 — регекс \w не матчит кириллицу)
- не следствие ли это устаревшего dev-сервера? (pitfall 17 — перезапусти)
- не следствие ли это временной ошибки конфига? (pitfall 16 — перечитай файл)

Потом: минимальный фикс + прогон затронутых скриптов + пункт в AGENTS-pitfalls.md.
```

### Аудит «что осталось»

```
Проверь проект D:\Astro tinacms на соответствие AGENTS.md и docs/AGENTS-production.md.

Найди:
- разделы админки на MOCK_* (grep -rn "MOCK_" src/pages/admin/)
- отсутствие авторизации на /admin и /api/admin/*
- расхождения документации с кодом (README, .env.example, docs/)
- битые внешние ресурсы

Формат ответа: таблица «найдено / файл / риск / что делать». Без правок кода.
```

## Рубрика «Оценка и улучшение промтов»

Оценка промта по шкале 0–10:

| Критерий | 0 | 5 | 10 |
|----------|---|---|-----|
| Конкретность цели | «улучшить сайт» | «починить слайдер» | «`/services`: точки 28×10px radius 6px, градиент синий→фиолетовый»» |
| Указаны ограничения | нет | «не ломать остальное» | «только механические правки, паритет с исходником, перечислить исключения» |
| Указана проверка | нет | «проверить что работает» | «`compare-src.mjs` → только механические отличия; `smoke.mjs` → 69/69» |
| Указаны границы | нет | «не трогать админку» | «файлы: A, B, C. Не трогать: D, E. Причина ограничения — pitfall 9» |
| Устранена неоднозначность | требует уточнений | частично | задача однозначна с первого прочтения |

**Правило улучшения:** сначала убрать слова «сделай хорошо / аккуратно / как надо» — они не несут информации. Затем добавить **измеримое** ожидание и **команду проверки**.

**Пример улучшения:**

| Было | Стало |
|------|-------|
| «Почини админку» | «Раздел `/admin/services` использует `MOCK_SERVICES` и ничего не сохраняет. Перевести на `src/lib/content.ts` по паттерну постов. Результат: форма сохраняет, изменение видно на `/services` без пересборки. Проверка: `grep -rn MOCK_ src/pages/admin/` пустеет на этой строке; создать услугу через UI → исчезает из `MOCK`-вывода и появляется на сайте» |
