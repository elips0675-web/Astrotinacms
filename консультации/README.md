# `консультации/` — разбор внешних консультаций

> Пять файлов `Анализ*.txt` и один `Промт.txt`. Это **мнение сторонних моделей**,
> а не правила проекта. Собраны в одну папку 03.10.2026, чтобы не лежали
> россыпью в корне и не выглядели частью проекта.
>
> **Ничего отсюда не применять автоматически.** Каждое утверждение проверяется
> по файлам проекта. Результат проверки — в таблице ниже и в `../Что сделано.txt`,
> этапы 7–9.

## Что здесь лежит

| Файл | О чём | Итог |
|---|---|---|
| `Анализ.txt` | Рекомендует отказаться от Astro и остаться на Next.js | **Отвергнуто.** Админка живёт внутри Astro-репозитория; тезис «две кодовые базы» не подтвердился |
| `Анализ1.txt` | Предлагает OG-теги и точечный CLS-фикс | **Частично принято.** OG-теги сделаны. CLS-фикс отвергнут: все 9 `<img>` лежат в контейнерах с местом, зарезервированным CSS |
| `Анализ2.txt` | Называет `site: localhost` критичной проблемой | **Принято.** `site` вынесен в `SITE_URL`, питфол 24. Сам файл к тому моменту был уже частично неправ — относительный `Sitemap:` нарушает RFC 9309 |
| `Анализ3.txt` | «Чинит» свой же код, предлагает относительный `Sitemap:` и `Disallow: /admin` в robots.txt | **Отвергнуто, частично регрессионно.** Относительный путь не по RFC 9309; `Disallow: /admin` вместе с `noindex` приводит к «No information is available for this URL». Патч OG терял фолбэк `description` |
| `Анализ4.txt` | Разбор предыдущих ответов + предложение начать тесты | **Принято одно.** `process.env` в `astro.config.mjs` читается на этапе сборки, а не в рантайме — питфол 25. Предложение «сократить набор до трёх файлов» отклонено |
| `Промт.txt` | Промты для связки с TinaCMS | **Неприменимо.** TinaCMS в проекте нет: `@tinacms/astro@0.7.1` требует Astro 5–7, проект на 4.16.19 |

## Сводка по фактам

Из шести файлов обоснованными оказались **две** находки, обе приняты:

1. `site` не должен быть литералом в конфиге → питфол 24.
2. `process.env.SITE_URL` читается при сборке, а не при запуске → питфол 25.

Остальное отклонено по трём причинам:

- **Уже было сделано.** `@astrojs/sitemap` подключён, `canonical` абсолютный,
  `lang="ru"` на месте — консультации предлагали чинить несуществующее.
- **Неверная модель проекта.** «Две кодовые базы», «CLS от картинок» — проверяется
  `grep` и не подтверждается.
- **Содержало регрессию.** Потерянный фолбэк `description`, `Disallow: /admin`
  рядом с `noindex`, относительный `Sitemap:`.

## Почему это важно хранить

Эти файлы — не шум. Три из шести предлагали изменения, которые выглядели
профессионально и сделали бы проект хуже. Три раунда подряд находки описывались
как «крупнее всех предыдущих», при том что в проекте не сломано ничего и нет
прода. Механика: отсутствие аварии толкает повышать ставки, чтобы совет не
выглядел пустым.

Практический вывод зафиксирован в проекте: **уровень срочности в таких
консультациях занижать**, а приоритеты брать из `../Что доделать.txt`.

## Как пользоваться

1. Прочитать файл целиком, включая код в примерах — в `Анализ4.txt` он
   потерян при копировании (вместо блоков осталось `123456789`).
2. Разделить на: уже сделано / не подтверждается / регрессия / новая находка.
3. Каждую новую находку проверить командой по файлам проекта.
4. Результат записать в `../Что сделано.txt` новым этапом и, если это грабля,
   в `../docs/AGENTS-pitfalls.md`.
5. Обновить счётчик граблей во всех местах, где он написан руками.
