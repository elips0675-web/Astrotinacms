Что стоит уточнить — без раздувания severity
1. SITE_URL в .env.example — но подхватывается ли он в рантайме?
process.env.SITE_URL в astro.config.mjs:12 читается на этапе билда, а не на сервере. Значит:

если деплой запускает astro build с SITE_URL=https://domain.com — всё работает;

если деплой билдит образ без SITE_URL, а передаёт её потом через runtime env — site зафиксируется как localhost:4321 в собранном sitemap.xml и не изменится.

Это не баг, а уточнение чеклиста выката: SITE_URL должна быть в build-time env, а не в runtime. Стоит добавить строку в pre-deploy checklist. Проверяется одной командой: SITE_URL=https://example.com npm run build && grep example.com dist/sitemap.xml.

2. robots.txt.ts — тип контента.
Если эндпоинт возвращает new Response(text), Astro ставит Content-Type: text/plain; charset=utf-8 — для robots.txt это корректно. Если случайно вернёте через Astro.response с Content-Type: text/html — Google всё равно распарсит, но лучше проверить. Скорее всего у вас правильно, упоминаю для проформы.

3. og:image — фолбэк не задан.
Разметка ставит og:image всегда, но файла нет. Это не ошибка кода — вы это уже пометили пунктом 7a. Просто напоминаю: пока файла нет, Telegram/VK покажет превью без картинки (не битую иконку, а просто пустое место). Как только og-default.jpg появится в public/ — заработает без пересборки (это статика). Хорошо, что отметили, чтобы не искать «почему не работает» через неделю.

4. curl ... | findstr og: — на Windows.
Команда корректна для Windows shell. На Linux/macOS в чеклисте будет grep -c "og:". Если команды идут в README для команды — стоит дать оба варианта, иначе половина разработчиков упрётся в command not found.
