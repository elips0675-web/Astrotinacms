Вот что я рекомендую внедрить в первую очередь.

🧩 1. Выбор стратегии рендеринга (самое важное для SEO)
В Next.js 15 за это отвечает App Router, и здесь работает простое правило: чем меньше динамики, тем быстрее сайт для поисковиков и пользователей.

Для главной страницы лендинга: используйте SSG (Static Site Generation). Это когда страница генерируется один раз при сборке и раздается как статический файл. Это самый быстрый и SEO-дружелюбный вариант, который обеспечивает мгновенную загрузку.

Для страниц с часто обновляемым контентом (например, блог или новости): используйте ISR (Incremental Static Regeneration). Вы просто добавляете в код export const revalidate = 60;, и страница будет перестраиваться в фоне раз в 60 секунд, оставаясь при этом максимально быстрой для посетителей.

Чего стоит избегать на лендинге: CSR (Client-Side Rendering). Он плохо индексируется, так как поисковые роботы видят пустую страницу до выполнения JavaScript.

🏷️ 2. SEO «из коробки» с Metadata API
Забудьте о ручном управлении тегами в <head>. Next.js 15 предлагает Metadata API, который автоматически генерирует все нужные теги для каждой страницы.

Для статических страниц просто экспортируйте объект metadata:

typescript
// app/page.tsx (главная страница)
export const metadata = {
  title: "Ваш Универсальный Лендинг | Ключевой запрос",
  description: "Краткое, привлекательное описание вашего предложения (до 160 символов).",
  openGraph: { // Для красивого превью в соцсетях
    title: "Ваш Лендинг в соцсетях",
    images: [{ url: "/og-image.jpg", width: 1200, height: 630 }],
  },
  alternates: { // Для правильной индексации
    canonical: "https://ваш-сайт.com",
  },
};
Для динамических страниц (например, блог с разными статьями) используйте функцию generateMetadata, которая сгенерирует теги на основе данных.

Дополнительный бонус: Вам не нужно вручную создавать sitemap.xml и robots.txt. Просто создайте файлы sitemap.ts и robots.ts в папке app, и Next.js сгенерирует их автоматически на основе вашей структуры.

⚡ 3. Скорость без усилий (Core Web Vitals)
Google использует метрики Core Web Vitals для оценки удобства вашего сайта. Вот как их улучшить с минимальными усилиями:

Для метрики LCP (скорость загрузки основного контента):

Всегда используйте компонент next/image вместо тега <img>. Он автоматически конвертирует изображения в современные форматы (WebP/AVIF), сжимает их и лениво загружает.

Для главного изображения (hero image) обязательно добавляйте атрибут priority. Это скажет Next.js загрузить его в первую очередь, что критически важно для LCP.

Всегда указывайте width и height для изображений, чтобы избежать смещения контента.

Для метрики CLS (визуальная стабильность):

Всегда задавайте width и height для изображений и видео. Это предотвращает «прыжки» контента при загрузке страницы.

Используйте next/font для подключения шрифтов. Next.js автоматически оптимизирует их загрузку и избегает сдвигов текста.

Для метрики INP (отзывчивость интерфейса):

Максимально используйте React Server Components (RSC). Они выполняются на сервере и не отправляют лишний JavaScript в браузер.

Используйте use client только там, где это необходимо (например, для интерактивных элементов вроде форм или кнопок).

🚀 4. Удобство и дополнительные оптимизации
Кэширование: Настройте агрессивное кэширование для статических ресурсов (JS, CSS, изображения). В next.config.js можно добавить заголовки Cache-Control: public, max-age=31536000, immutable. Это сделает повторные визиты пользователей практически мгновенными.

Пакеты: Используйте experimental.optimizePackageImports в next.config.js для автоматического «вырезания» неиспользуемого кода из больших библиотек, что значительно уменьшит размер бандла.

Инструменты: Проверьте свой сайт с помощью Lighthouse в Chrome DevTools или онлайн-сервиса PageSpeed Insights, чтобы увидеть, что еще можно улучшить.
